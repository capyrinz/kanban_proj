## Роли и права доступа

| Роль | Проекты (созд./ред.) | Проекты (удал.) | Колонки (созд./ред.) | Колонки (удал.) | Задачи, комментарии |
|---|---|---|---|---|---|
| `administrator` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `manager` | ✅ | ❌ | ✅ | ✅ | ✅ |
| `developer` | ❌ | ❌ | ✅ | ❌ | ✅ |
| Гость (без токена) | ❌ | ❌ | ❌ | ❌ | ❌ (только чтение) |

* Чтение (`GET`) доступно без авторизации; все мутации требуют заголовок `Authorization: Bearer <token>`.
* Роль `administrator` недоступна при саморегистрации — создаётся только при посеве БД (`admin`/`admin`).

## 1. Аутентификация (`/auth`)

### 1.1. Регистрация
* **Метод:** `POST` /auth/register — **без токена**
* **Тело:**
```json
{
  "username": "dev1",
  "password": "secret123",
  "role": "developer"
}
```
* `role`: `developer` | `manager` (любая другая, включая `administrator`, → `403`)
* `username`: минимум 3 символа, `password`: минимум 6 символов (иначе `422`)

**`201 Created`:**
```json
{ "message": "Пользователь dev1 успешно зарегистрирован" }
```
**Ошибки:** `409` — пользователь уже существует; `403` — запрещённая роль.

### 1.2. Вход (выдача JWT)
* **Метод:** `POST` /auth/login — **без токена**
* **Тело:** `{ "username": "admin", "password": "admin" }`

**`200 OK`:**
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "role": "administrator",
  "username": "admin"
}
```
**Ошибки:** `401` — неверный логин или пароль (с заголовком `WWW-Authenticate: Bearer`).

Использование токена в дальнейших запросах:
```
Authorization: Bearer <access_token>
```

## 2. Проекты (`/projects`)

### 2.1. Список проектов
* **Метод:** `GET` /projects — без токена
* **`200 OK`:** `[{ "id": 1, "title": "Основной проект Kanban", "description": "..." }]`

### 2.2. Создать проект
* **Метод:** `POST` /projects — роли: `administrator`, `manager`
* **Тело:** `{ "title": "Новый проект", "description": "Описание" }` → `201 Created`
* **Ошибки:** `401` без токена, `403` для `developer`, `422` при пустом `title`.

### 2.3. Обновить проект
* **Метод:** `PUT` /projects/{project_id} — роли: `administrator`, `manager`
* **Тело:** `{ "title": "Новое имя", "description": "..." }` (оба поля опциональны) → `200 OK`
* **Ошибки:** `404` — проект не найден.

### 2.4. Удалить проект
* **Метод:** `DELETE` /projects/{project_id} — только `administrator`
* **`200 OK`:** `{ "status": "deleted" }`
* Удаление каскадно удаляет колонки, задачи, комментарии и историю проекта.

## 3. Колонки (`/columns`)

### 3.1. Список колонок
* **Метод:** `GET` /columns — без токена
* **Параметры:** `?project_id=1` — фильтр по проекту.
* **`200 OK`:** массив, отсортированный по `order`:
```json
[
  { "id": 1, "title": "Бэклог", "wip_limit": 5, "order": 1, "project_id": 1 },
  { "id": 2, "title": "В работе", "wip_limit": 3, "order": 2, "project_id": 1 }
]
```

### 3.2. Создать колонку
* **Метод:** `POST` /columns — любой авторизованный пользователь
* **Тело:**
```json
{ "title": "Ревью", "wip_limit": 2, "order": 4, "project_id": 1 }
```
* `title` обязателен (непустой), `wip_limit` — 1…1000 (по умолчанию 3), `order` — опционально (иначе автоматический), `project_id` — опционально (по умолчанию первый проект).
* **`201 Created`** с полным объектом колонки. **Ошибки:** `404` — проект не найден; `422` — валидация.

### 3.3. Обновить колонку
* **Метод:** `PUT` /columns/{column_id} — любой авторизованный пользователь
* **Тело (все поля опциональны):** `{ "title": "QA", "wip_limit": 4, "order": 2 }` → `200 OK`
* **Ошибки:** `404` — колонка не найдена.

### 3.4. Удалить колонку
* **Метод:** `DELETE` /columns/{column_id} — роли: `administrator`, `manager`
* **`200 OK`:** `{ "status": "deleted" }`; вместе с колонкой каскадно удаляются её задачи. **Ошибки:** `403`, `404`.

## 4. Задачи (`/tasks`)

### 4.1. Список задач с фильтрами и поиском
* **Метод:** `GET` /tasks — без токена
* **Параметры (все опциональны, комбинируются):**

| Параметр | Пример | Описание |
|---|---|---|
| `project_id` | `?project_id=1` | Задачи проекта |
| `column_id` | `?column_id=2` | Задачи колонки |
| `search` | `?search=REST` | Подстрока в названии/описании (регистронезависимо, кириллица поддерживается) |
| `assignee` | `?assignee=валерия` | Исполнитель (регистронезависимо) |
| `priority` | `?priority=high` | `low` \| `medium` \| `high` |
| `tag` | `?tag=backend` | Метка из списка через запятую (регистронезависимо) |

* **`200 OK`:**
```json
[
  {
    "id": 1,
    "title": "Разработать REST API",
    "description": "FastAPI + Pydantic v2",
    "column_id": 2,
    "project_id": 1,
    "assignee": "Валерия",
    "priority": "high",
    "deadline": "2026-10-01",
    "tags": "backend, api",
    "attachment_url": "https://fastapi.tiangolo.com"
  }
]
```

### 4.2. Создать задачу
* **Метод:** `POST` /tasks — любой авторизованный пользователь
* **Тело:** `{ "title": "Новая задача", "column_id": 1, "project_id": 1, ... }` — `title` и `column_id` обязательны, остальные поля опциональны (`assignee` по умолчанию `"Не назначен"`, `priority` — `medium`).
* **`201 Created`** с `id` и `project_id`.
* **Ошибки:** `404` — колонка/проект не найдены; `400` — превышен WIP-лимит колонки; `422` — валидация.

### 4.3. Обновить задачу
* **Метод:** `PUT` /tasks/{task_id} — любой авторизованный пользователь
* **Тело:** частично или полностью:
```json
{
  "title": "Новое название",
  "description": "Новое описание",
  "assignee": "Иван",
  "priority": "low",
  "deadline": "2027-01-01",
  "tags": "docs",
  "attachment_url": "https://example.com/f.png"
}
```
* **`200 OK`**, **`404`** — задача не найдена, **`422`** — неверное `priority`.

### 4.4. Переместить задачу (drag-and-drop)
* **Метод:** `PUT` /tasks/{task_id}/move?target_column_id={column_id} — любой авторизованный пользователь
* **`200 OK`** с обновлённым объектом задачи; записывает событие в историю (`Перемещена из ... в ...`).
* **Ошибки:** `400` — превышен WIP-лимит целевой колонки; `404` — задача или колонка не найдены.

### 4.5. Удалить задачу
* **Метод:** `DELETE` /tasks/{task_id} — любой авторизованный пользователь → `200 OK` (`{ "status": "deleted" }`), `404` — не найдена.

### 4.6. История изменений задачи
* **Метод:** `GET` /tasks/{task_id}/history — без токена
* **`200 OK`:**
```json
[
  { "timestamp": "2026-10-09 12:00:00", "action": "Задача создана" },
  { "timestamp": "2026-10-09 12:05:00", "action": "Перемещена из Бэклог в В работе" }
]
```
* История заполняется автоматически при создании, редактировании и перемещении. Для неизвестной задачи возвращается `[]`.

### 4.7. Комментарии задачи
* **Получить:** `GET` /tasks/{task_id}/comments — без токена → `200 OK` (массив, `[]` если пусто).
* **Добавить:** `POST` /tasks/{task_id}/comments — любой авторизованный пользователь
* **Тело:** `{ "text": "Комментарий", "author": "admin" }` → `201 Created` c `timestamp`.
* **Ошибки:** `404` — задача не найдена, `422` — пустой `text`.

## 5. Коды ответов API

| Код | Описание |
|---|---|
| `200 OK` | Запрос успешно выполнен. |
| `201 Created` | Ресурс успешно создан. |
| `400 Bad Request` | Бизнес-ошибка, например превышение WIP-лимита колонки. |
| `401 Unauthorized` | Нет токена, токен невалиден или истёк (для мутаций). |
| `403 Forbidden` | Роль пользователя не даёт права на операцию. |
| `404 Not Found` | Объект с указанным ID не найден. |
| `409 Conflict` | Конфликт, например дубль имени пользователя при регистрации. |
| `422 Unprocessable Entity` | Ошибка валидации Pydantic (пустой `title`, неверный `priority` и т.п.). |
| `500 Internal Server Error` | Внутренняя ошибка сервера. |

**Пример ошибки валидации (`422`):**
```json
{
  "detail": [
    { "type": "string_too_short", "loc": ["body", "title"], "msg": "String should have at least 1 character" }
  ]
}
```
